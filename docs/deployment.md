# 部署、更新与恢复

当前交付源码和部署说明。部署时使用明确标签或完整提交；预编译桌面安装包不在本次交付范围内。

本项目与上游是独立产品。已有其他终端安装时，先使用独立目录和数据卷；不能假设所有上游或历史数据库都能直接升级。跨平台迁移也必须核对SQL原字节、迁移checksum及真实订单责任。

## 源码运行

准备受支持的Node.js、npm及Git，在源码目录运行 npm ci --no-audit --no-fund 和 npm run build，再用Windows的run.ps1或Linux的./run启动。访问启动器输出的回环地址，默认17840。
通过安全录入页面配置自己的API，启动不自动启用交易。网页关闭不停止后台；电脑休眠或后台停止会中断保护，交易所仓位仍存在。

## Linux与Docker

```sh
docker compose up -d --build
docker compose ps
```

默认Compose只发布主机回环端口，数据保存在专用持久卷。不要把终端端口开放到公网。云端通过自己的SSH隧道访问：

```sh
ssh -N -L 17840:127.0.0.1:17840 USER@YOUR_SERVER
```

本机访问 http://127.0.0.1:17840 。端口冲突时换本地端口，保留远端回环目标。健康接口不能单独证明交易业务正常。

## 更新与备份

先准备并验证新版本，再安排维护。记录旧版本、账户、任务、实际仓位、挂单、归属、退出意图和风险责任。通过正式交易模式入口停止新交易并确认挂单终态，不用任务Stop代替维护暂停。
保留数据卷和兼容旧镜像。数据库使用一致性备份，同时独立保护凭据、配置和版本信息；这些材料不进Git或公开工件。源码环境可使用：

```sh
node scripts/backup-database.mjs SOURCE.sqlite NEW_BACKUP.sqlite
```

脚本拒绝覆盖备份并检查完整性。Docker镜像包含相同脚本，应在专用数据卷内选择新的私有备份路径，并安全转存。数据库备份不包含所有凭据或配置。
先在隔离副本验证迁移和恢复，再切换；不改写既有SQL校验和。保留原数据卷，禁止用 docker compose down -v 作为更新步骤。

## 恢复与回滚

启动保持交易unset。核对版本、账户、订单、仓位和责任后，由使用者明确恢复原授权；已有人工锁和停止/退出意图不能清除。
未清配对资金责任要求目标支持相应账本。旧版能打开新表不代表安全回滚。有后续交易时不能拿升级前数据库覆盖当前记录，不能因恢复失败而删掉责任。
灾难恢复先停止后台，在隔离位置验证备份和目标版本，并保存当前数据。恢复后重新核对交易所状态。备份完整不等于业务事实一致，恢复和降级也不等于允许重新启用实盘。

## Windows 深层目录与版本显示

Windows 安装器使用系统自带的 tar.exe 解压深层依赖目录，并拒绝链接等特殊 ZIP 条目。仅解封经过现有校验的暂存归档，保留原下载文件；清理使用 Windows 原生扩展路径，不修改系统长路径设置。推荐保留默认目录或使用较短的本地安装根；归档内部深路径通过验收，不代表任意长度安装根或网络共享路径均受支持。缺少解压工具、校验或解压失败时，准备过程停止，既有安装不会被切换。

健康接口读取已安装后端包的版本，Docker 直接启动同样生效。具体构建身份仍以源码提交和镜像摘要为准。
