# 托管对冲持仓规格

本文件定义 PIXIU ARB 终端的现行托管行为。开发入口为本仓库根目录。API 请求与错误码见[接入文档](integration.md)，实现结构见[架构](architecture.md)。

## 独立持续保护

正常已登记保证金批次的精确可归属成交只作废旧快照并重读；live期间的临时账户核对由原管理器优先完成，不能因持续保护接管而直接写入人工硬暂停。原固定25秒期限及真实故障升级保持。正常保证金恢复可结束本事件的增仓冻结并继续监控剩余量，条件见[保证金恢复契约](margin-risk-management.md#执行结算与恢复)；这不是持续保护恢复普通策略的权限，也不清除已有风险暂停。

新托管任务的启动确认同时授权本次稳定组的普通IMR/MMR保护和暂停期间持续保护；启动事务在首笔下单前原子登记任务、claims及两项授权。接管、追加和移交沿用稳定groupId，只保护当前claims控制器。已有遗漏组仍须在风险页明确选择并授权，不由轮询迁移。普通策略的暂停/人工复核锁与保护执行分离。保护以同账户、原claims、持久授权代次、两次独立匹配的持仓/订单快照和有效保证金数据为依据；状态包括待命、自动核对、执行、受阻和撤权。`protect_only`表示仅受限保护许可可发单，普通策略仍暂停，不能当成live或全账户readonly。

外部减仓配平后仍保留普通策略风险锁，但持续核对新的失衡和保证金风险；临时证据缺失时自动核对，恢复后仅继续保护。未知提交/撤单只查询原身份，不重放；数量必须精确、最小金额和必要报价有效，原保证金批次及费用预约不清除。共享账户仍存在未决订单时，不开始无法证明账户预算安全的新保证金首腿；其他组的独立已核实失衡可以继续评估。

持续保护的显式授权来自新的任务启动确认或风险页范围确认，旧配置、KEEP、readonly和历史保护勾选不自动迁移。KEEP仍关闭该任务的自动保护；明确readonly或关闭持续保护立即撤销授权，并使排队许可失效。新的启动确认只可重新授权本次组，不恢复已撤权的其他组；准备启动期间发生撤权、范围/账户/模式变化则整次创建回滚。重启先从unset读取及核对，仅在原授权未撤销且账户身份/责任核清后进入protect_only，不恢复普通策略。一次性许可绑定账户、组、合约、方向、数量、事实版本、有效期和唯一订单，实际发送前重验。

登记不等于可执行：空仓/OPENING任务显示待核对，正常建仓仍由原执行器推进。暂停后只能根据接管基准和已确认成交账本核实实际数量，未成交目标不计为可减仓量；未知订单只核对、不重放。已成交的配对责任不因新增组或授权版本变化而丢弃。风险页披露当前组数、登记数、核实数及未覆盖原因，通知开关不影响保护执行。

后文对“硬暂停禁止自动交易”和“重启不恢复”的描述继续适用于普通策略和未启用独立持续保护的账户。部署及真实持仓接管另需授权；本地实现不代表线上已启用。

## 用户流程与默认值

1. 在配对建仓页选择币种、两个交易所、多空方向和本次新增数量。新表单默认开启“持续监控与自动退出”以及“接管所选两腿的平衡旧仓”。启动确认同时登记本组IMR/MMR自动减仓授权，覆盖接管旧仓与新增仓位；建仓核实及原执行门禁通过后才允许保护。
2. 后端核对真实账户、合约、旧仓和未结订单。满足条件后接管，按本次目标增加仓位；已有数量不计入新增进度。
3. 建仓期间及完成后，统一核对实际总仓位、观察退出信号，并协调建仓与保护操作。
4. 点击“停止”先打开确认框。“同时自动平仓”默认不勾选：保留仓位并停止自动管理；勾选才按配置退出全部托管仓位。

配置兼容性：没有 `management` 的历史任务保留原有一次性执行语义；没有 `management.adoptExisting` 或该值为 `false` 时，只允许从所选两腿空仓开始。新表单默认选中接管，不会替历史任务补写授权。开发、推送或部署授权不等于真实接管、下单或恢复交易授权。

## 接管范围与准入

- 范围由当前凭据账户、两腿实际 CrossEx 合约及方向确定，不按币种汇总行的净数量判断。每个具体合约只能有一个控制者。
- 支持终端现有配对执行器的同标的 CrossEx 基础资产数量，要求两腿方向相反、数量一致。A/B 展示顺序互换且实际方向不变时仍可识别同一组。本功能没有增加任意反向合约或跨资产比例换算。
- 无法核实的数量、错误方向、同合约多条非零仓位、非平衡旧仓或外部异常增仓均不直接接管。缺失或失败的账户请求不视为空仓。
- 非托管平衡旧仓可以显式接管。已托管组仅在同账户、相同实际两腿、状态为 `MONITORING` 或保留仓位的 `STOPPED`、无退出意图时允许追加任务接管。建仓中、退出中和风险暂停的组不能被抢占。
- 同标的在第三家交易所或其他账户的仓位不属于本次接管范围。其他策略仍控制的合约不能借接管绕过互斥。
- 在准备期间建立两腿预约，原控制者继续监控。原任务停止、完成、触发退出或需要失衡保护时，中止追加接管并优先处理原有责任。
- 已知、可归属的本地旧挂单仅在所选合约范围内撤销并确认终态，再重读真实持仓。对称挂单不等于已完成对冲；远端未知订单、未确认提交/撤单和冲突订单阻止启动。取消后仍无法核对则进入全局风险暂停。
- 行情、合约规则和退出批量校验须在杠杆或新订单操作前完成。提交任务前复核账户、预约和持仓基线；正式接管与控制权交接在一个数据库事务中完成。失败释放预约，原控制权保留。

## 数量、成本与控制权

新增进度只统计本次任务的成交。持仓风险以新鲜真实两腿为准，同时核对其是否能由“接管基线 + 本次已确认净成交”解释；已确认净成交包含减仓，不能把累计开仓量直接当作现有仓位。

接管保存数量、时间及可取得的原始成本/未实现盈亏；缺失值保留为未知。界面显示接管数量、本次成交、实际两腿总数量和差额。稳定的 `groupId` 串联追加任务，原任务进入 `TRANSFERRED`，可追溯历史，但不能再次恢复控制权。

保证金和仓位风险档位继续按现有执行器检查。异常增仓不能通过放大持仓上限来消除报错。保证金批次和外部减仓事故只处理可精确交易的真实差额，不以最小金额或精度为由扩大减仓或全部退出；不可交易残量进入人工锁。独立的完整退出意图仍按其已授权规则处理。

## 配对执行准入与延迟

本地新增执行契约见[配对执行与资金责任](paired-execution.md)。完整两腿准入前移到首腿；已批准范围内的正常第二腿不重复联网审批。普通退出按已确认成交增量配对，真实持仓对账保留为本批完成/下一批首腿门槛。真实风险锁和保证金保护批次不适用普通配对豁免。生产是否生效以对应发布证据为准。

## 建仓、观察与退出

| 阶段 | 行为 |
| --- | --- |
| `OPENING` | 按新增目标建仓，同时核对包含旧仓的总持仓；已知本批配对成交由原执行器协调 |
| `VERIFYING` | 新鲜实际持仓与终态订单核对；不把预计成交当事实 |
| `MONITORING` | 观察两腿平衡、价差、净资金费率及持续时间 |
| `BALANCING` | 已确认失衡时，优先市价只减仓较大一腿；订单未知不重放 |
| `EXITING` | 停止新增，按配置以 Maker–Taker 分批退出新老仓位合计 |
| `STOPPING` | 已持久化停止选择，正在核对/取消任务未结订单；阻止新的提交 |
| `STOPPED` | 仓位保留，自动监控、保护和退出全部停止，控制权仍保留 |
| `RISK_PAUSED` | 风险暂停，核对事实并明确恢复前禁止自动交易 |
| `TRANSFERRED` | 控制权已交给追加任务，旧任务不可恢复 |
| `COMPLETED` | 真实两腿归零且无未决或远端订单，释放控制权 |

建仓过程中确认实际仓位与记录不符，或经济退出条件成立，先停止建仓执行器并处理在途订单，再移交保护/退出，避免两个执行器互相下单。建仓异常保护完成后保留风险暂停，明确复核恢复时才清除事故标记。

默认经济退出条件是：按任务固定方向计算的最佳可执行报价价差 **低于 −20 bps**，且八小时归一化的净资金费率年化 **低于 −100%**，连续 **60 秒**。阈值、AND/OR、持续时间、每批数量、挂单腿、批次间隔、挂单等待和市价回退在启动时配置；追加任务的配置作用于该组全部托管仓位。

触发后退出意图持久化，不因信号回升恢复建仓。阈值不是固定平仓限价。Maker 只减仓成交由另一腿及时减仓配对，撤单必须确认后再挂。默认不允许挂单超时后的市价回退；用户未允许时持续等待，不虚构完成时间。明确的“停止并保留仓位”可停止正在执行的自动退出，并保存 KEEP 意图。

行情或资金费率缺失/过期时不触发经济退出，持续计时重置；已确认的账户失衡保护与经济信号分别处理。

### 账户保护与结算等待

IMR/MMR自动保护的范围、排序、成本输入、批量及恢复判据统一见[保证金风控](margin-risk-management.md)。原manager负责两腿市价配对，batchId与持久订单关联；不能通过普通差额取整或整腿回退扩大保证金批次。经济退出在撤单/部分成交核清后交接，并保留完整退出意图。保证金批次按恢复目标及真实容量规划，费用预约跨事件/重启保留；每批交易事实与异步账单分别核实，不能因普通账单延迟解除真实订单锁或反过来误停正常保护。

已归属成交尚未反映到仓位时，`positionSettlementSince`或批次 `settlementSince`记录等待，阻止新批次；仅具有当前精确本批差额证明的普通第二腿可越过正常持仓结算等待，不能越过真实风险锁或保证金批次保护；核对期限为25秒，期满升级人工。完成批次须由本批终态成交解释两腿实际减少，再等待账户恢复证据。无法解释的外部减少（即使两腿仍平衡）记录 `protectionIncident`、冻结新增，在有效原权限内有限配平后保留人工锁。KEEP、硬锁、live撤销及控制权转交仍阻止提交，事故核对不自动解除这些边界。

### 报价恢复与退出前检查

- ticker 缺失时，共用恢复器可通过同一 CrossEx 合约的官方完整盘口取得最佳买卖报价；按交易所支持的通道选择，不写死币种。支持范围、来源字段与限制见[行情接口契约](integration.md#executable-quote-provenance)。交易所原生同名合约或另一家交易所的价格不能直接代替所选合约；经[独立来源准入](data-recovery.md)验证的精确原生合约可作为备用，不复用页面参考价。
- 开始一批双腿减仓前，两腿都须有有效报价；限价首腿、市价回退首腿和保证金减仓首腿适用相同检查。若等待凭据期间报价失效，最终提交检查阻止落单。
- Maker 存续期间任一腿报价失效，先撤剩余挂单，确认终态及累计成交，再读取新持仓；已经部分成交也走这条核对路径。撤单或提交未知不能重放。
- 修复已确认差额时，实际待减腿须有有效报价，即使其最小名义金额规则为空也不能绕过。两腿交易不具备原子性；行情或交易限制无法核实时仍须风险暂停，不能承诺零残量立即成交。
- 风险暂停先保存 `PAUSED` 再发布界面状态。随后已确认的订单终态可以更新未决列表，但不解除风险锁、不刷新持仓核对时间，也不代表平仓成功。

## 手动停止与恢复

持仓表暂不提供单腿一键平仓。交易页、策略页、资产页的交易对“全部平仓”共用原任务的停止确认框，固定选择同时自动平仓，提交原 `stop(closePositions=true)`；不再逐腿手工下单或另建分批 `closePlan`。普通停止入口仍默认 KEEP。

页面资产分组不是托管归属。只有当前账户、两条精确合约及持仓方向唯一对应实际 claims 的任务才可使用“全部平仓”；无法匹配、多个任务、额外合约或风险暂停时禁用并说明原因。服务端确认时再次核对账户与 claims。已接受请求和未知结果不被旧轮询重新启用；退出受理不等于成交完成，实际进度和异常处理沿用原任务。历史 closePlan 的读取、核实及通用执行能力保留。

| 停止请求 | 结果 |
| --- | --- |
| 省略请求体、`{}` 或 `{"closePositions": false}` | 默认 KEEP：停止自动化、核实并取消任务挂单，保留实际仓位；不提交减仓 |
| `{"closePositions": true}` | EXIT：停止新增并核清在途订单，再分批退出该任务管理的新老全部仓位 |

`closePositions` 必须是布尔值。普通停止入口每次打开都默认不勾选平仓；持仓表“全部平仓”入口固定勾选平仓；确认文案说明停止保留也会停止保护。保留的仓位仍有市场风险，保持可见，并提供明确恢复或由新任务接管的入口。

KEEP 遇到失衡或无法确认的订单会保留停止意图并进入风险核查，不能假装安全完成。平仓选择也不会绕过已有人工风险锁。停止后经真实零仓和零未决订单证明，可直接进入 `COMPLETED` 并释放 claims。

恢复须显式授权，并按保存的意图区分“继续建仓／恢复监控／继续平仓”：KEEP恢复监控；已有退出意图继续原退出，可能立即只减仓；未完成建仓按下节核清后续原目标剩余量。已释放或已转交控制权的任务不能恢复。行情恢复、部署或服务live均不自动解除硬暂停。持续保护读取完成后的纯调度不使恢复事实失效；订单、成交、持仓等真实事件仍使账户事实版本失效，恢复继续核对账户、claims、配置、意图和风险。

## 超时、重启和权限边界

- 新增仓位的 Maker–Taker 若对冲腿为 Hyperliquid，首腿挂单前按精确原生合约读取官方 `perpsAtOpenInterestCap`；已达上限或读取失败时零挂单、五秒后重查，不暂停任务。减仓、退出和其他交易所不走此检查。若挂单成交后才遇到竞态，仅白名单容量错误且对冲订单明确 FAIL、零成交时，停止该任务建仓、保留 claims 和原持续保护授权，通过现有保护精确平回两腿差额；不写全局锁、不暂停其他任务。已有平衡仓位保留并等待人工恢复；确认两腿归零及订单终结才完成任务。范围、配置或账户变化、外部仓位、保护拒绝/未知及固定25秒未完成均升级原全局暂停。此责任随任务状态持久化，重启不重置期限；其他故障保留原行为。
- 账户核对在后台每两秒运行，并接收有关私有事件的合并唤醒；账户读请求有高优先级、逐请求四秒和聚合八秒期限，远端订单操作有独立的三秒监控期限。迟到结果不能授权交易。
- 可恢复账户读取故障进入持久化 `managed_account_rechecking`，从首次故障固定计算25秒，约2秒只读重试；不再因三次快速失败提前硬停。排队、响应体及同批请求可取消，429仍遵守原冷却；401/403等认证错误明确升级。期限检查不被在途读取阻塞，撤权后的旧结果无权创建或解除锁。
- 清临时锁前须取得两次独立、匹配且能被原阶段账本、订单身份/成交及控制责任解释的新鲜快照。已知结算/撤单待确认继续等待；未知提交或不可解释仓位继续保护。不得自动清硬锁，也不得用切模式或重启延长窗口。
- 临时复核通知原控制器对存量Maker发起至多一次受控撤单；已有撤单意图只查询。建仓取消保留原25秒，退出取消保留原5秒，不重放不明请求。确认部分成交后只续原配对责任。经济信号使用原行情/费率独立计算；零持仓且未成交的OPENING不因此产生退出意图。复核期间可保留已有退出意图，但不覆盖阶段或绕过交易门禁；保证金指标及其原判断保持独立。
- 账户读取期间事件使快照失效时，始终丢弃本次事实并合并重读。当前账户、当前 claims 所属、RUNNING/OPENING 且无退出/事故责任的零成交 LIMIT/POC 建仓单，其已知 NEW/OPEN、正常待撤及确认零成交 CANCELLED 更新只触发后台重读，不升级全账户复核。存在真实读取失败的临时锁时，正常更新仍不能绕过两次新鲜匹配。具有有效整对准备的自有正常成交、可精确解释的仓位变化，以及自有正常零成交退出挂单，按配对执行契约只作废旧事实并后台重读，不自触发异常复核；归属不明、真实读取失败、外部变化及已有风险锁保留原保护。持续不能取得有效事实的 25 秒期限从首次失效固定计算，更新不能延期；有效读取后才清除这个后台期限。失效或尚未完成风险复核的仓位事实不提供给保证金规划；真实账户保证金指标仍沿独立读取更新。
- Maker 改价及不再需要的报价进入异步撤单确认；执行器不占住任务队列等待HTTP，成交配对和其他任务监控继续运行。撤单意图先持久化为PENDING_CANCEL，OPEN/部分成交更新不清除此意图，累计成交照常更新。首次撤单响应不明或查询事实不完整时绝不重发并升级原人工保护；只有首次DELETE已明确返回、远端查询再次证明同一orderId、合约、方向、总量与剩余量仍为OPEN/PARTIALLY_FILLED，才可在固定窗口第2秒和第8秒各补撤一次。每次发起先写持久审计，重启不能重新获得次数。旧单未终结时不挂替代单；确认终结后按最新成交和行情重评；25秒仍无法确认则升级硬暂停，迟到结果不解除已有硬锁。该窗口不替代经济退出条件或保证金风控条件。
- 执行器遇到明确的预提交 `managed_account_rechecking` 时，只结束本次评估并等待复核，不增加挂单失败、修复尝试或额外冷却，也不清除已有真实失败计数。恢复后按当前行情和原权限重新评估。双腿操作只有两腿均未提交且均被该临时检查阻挡时才能整体暂缓；已有接受、成交或未知结果仍保留原订单及配对责任，不能按零提交跳过或重放。
- 人工恢复未完成建仓任务时，原账户及两腿claims须完整；历史订单有远端ID，终态为FILLED/CANCELLED且无失败标记，无退出/KEEP/未清事故或减仓责任。实际两腿须平衡，并与接管基线加本任务逐腿已确认成交完全一致，成交汇总与任务账本一致且不超过原目标。核对通过后保留原ID、配置、目标和成交记录，恢复OPENING，由原执行器按原条件仅建剩余量；已达目标则监控。读取期间版本、配置、状态或意图变化返回managed_review_changed，本次不清锁、不下单且不自动重试；须重新点击恢复取得新事实。界面显示动作由resumeAction给出，expectedAction不一致则拒绝。verified=false不能自行产生退出意图。
- 活跃任务驱动共享资金费率约每 30 秒刷新，失败交易所约五秒后重试；超过 60 秒的数据不用于经济退出。
- 重启始终从交易 `unset` 开始，保留 claims、退出意图和 KEEP 停止意图；持续计时重置。未完成的停止不会自动继续交易；恢复建仓前还须核对真实总持仓和订单。
- 当前账户/凭据有未清托管责任时禁止切换或等价变更；新订单、减仓、撤单、杠杆及恢复操作必须遵循所属任务与权限边界。
- 全局硬暂停、重启后超时的账户复核，以及持续五分钟缺少经济退出信号，会按现有 Telegram 配置告警。配置使用通知设置选定的 `env_file` 或 `os_keychain`；文件方式只放专用数据目录内忽略的 `telegram-alert.env`。告警区分故障开始与实际硬暂停时间，并带最后读取失败的端点、HTTP和阶段；旧事件缺少该证据时不虚构。通知成功不等于用户已读，也不授予任何交易权限。
- 经济退出信号连续缺失的首次时间不随缺失腿或原因变化重置；必要报价与独立实时费率均恢复后才结束该事件。当一腿所有合格报价候选均失效时，可立即通知；持续五分钟信号缺失和必要数据恢复分别通知，各阶段按任务/首次时间去重并遵守通知配置。价格恢复但费率仍缺失不结束经济信号事件；退出条件的持续时间仍在数据缺失时独立重置。恢复盘口必须进入原退出判断链才算接管；页面原生 REST 参考报价不因此取得自动交易权限。
- 报价与经济信号缺失通知针对 `RUNNING` 任务；存在全局风险锁时优先处理风险锁告警，普通缺失和恢复通知暂不扫描。这些通知调度规则不改变任务本身的恢复、退出与风控判断。

## 验证与证据入口

本规格的关键回归包括多币种接管、追加进度、未知订单、取消/成交竞态、并发启动、原组保护不中断、退出与保留两种停止选择、恢复与交接竞态、重启核对、最小交易残量及旧策略兼容性。

代码验收运行 `npm run verify` 和相关对抗审查；故障验证使用临时数据库、模拟网关和隔离浏览器。生产更新需要实际备份迁移演练、固定镜像、即时真实持仓/订单核对及明确授权。测试通过不代表真实接管或平仓已经做过实盘验收。

- [公开部署指引](deployment.md)：安装、更新、恢复和回滚。历史实现通过 Git 和根目录 `CHANGELOG.md` 追溯，不作为新的实盘授权。

## 保证金读取引发的临时复核

暂时保证金读取失败保留OPENING意图、目标和责任，复用固定25秒账户复核；匹配账户/订单事实之外，还须取得两份不同的新鲜保证金观测。数据不足不得写成零仓完成。认证、身份/模式错误及既有硬锁仍升级人工；具体读取隔离、取消和主备来源规则见[数据恢复契约](data-recovery.md)。
