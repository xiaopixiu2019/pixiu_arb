# 配对执行与资金责任

本规格约束本轮本地实现；生产生效须另有发布与运行证据。

- 官方账户指标、现有保证金公式、费用余量、预警/保护线保持原口径。任务新增责任与已计入官方账户的资金分别计数；不引入联合压力预测。
- 普通托管 Maker–Taker 在首腿前准备两腿并持久登记资金责任。正常第二腿仅消费原任务数量和资金范围，不执行同步账户/杠杆/模式查询。账户或准备过期、真实故障、控制权改变和未知订单仍阻止执行。
- 正常自有订单生命周期、明确成交及其可解释的仓位变化使旧事实失效并后台重读，不自行触发全局异常恢复。已严格核实的零成交首腿路由拒单按[专用处理规则](managed-positions.md#建仓路由拒单)隔离，不改变账户快照版本；已有真实锁不因此解除。
- 普通退出按已确认成交配对，对手腿始终只减仓；真实持仓核对仍是完成本批与启动下一批的门槛。保证金保护批次及成本预约不使用该例外。
- 鉴权读取有界并发，交易写入串行；所有派生客户端共用账号发起间隔及429冷却。真正发送前复核权限；尚未发送的取消与已发送未知结果严格区分，未知订单不得重放。
- 写请求结果先传播给调用方，下一事件轮才释放写槽。真正未知的提交/取消先持久记录，再同步全局硬暂停，不依赖下一次账户轮询；明确拒绝、确定未发送和已被私有流确认的进展不标成未知。迟到终态不能自动恢复交易。
- 重启从unset开始，未清资金及订单责任保留。小额实盘验证不得接管或干扰现有任务，测试权限不扩展为生产维护权限。

验收需要旧实现失败/新实现通过的时序回放、并发/部分成交/乱序/停止/重启及风险回归、完整verify。正常路径额外准入HTTP为0；本地确认成交到发送p95≤200ms、p99≤500ms为待验证目标，不是交易所成交保证。

## 本地实现边界

### 单次同步准入检查

完整复核入口保持独立。仅在一次同步检查内复用风险快照及无写入时的本任务资料，禁止跨凭据读取、订单落盘、排队或下次检查复用。检查内出现责任写入、上下文变化或数据越过原有效期须拒绝，不能沿用先前的fresh标记。实际发送仍保留全部权限、数量、资金和未知订单守卫，并正确排除当前已落盘单的重复计量。普通退出的批间核对、间隔和最终归零确认不变。

官方账户有效性沿用5秒；合约准备从本轮读取开始计时，10秒到期，活动建仓由后台按至少4秒间隔刷新，失败或过期不延长旧证明。每个读取客户端保持原有串行，账号合计最多两个读取槽及一个写槽，共享原100ms发起间隔与429冷却。交易写槽覆盖完整响应验证，不等待订单最终成交。

同一任务、账户、配置和上下文代次的在途准备共用一轮读取，两腿杠杆合并查询并逐合约检查；排队后再次验证原上下文及证明有效性。已结束的失败不再供新尝试复用，未结束的同批读取仍须排空后才开启下一轮。失效后的旧结果不得重新签发准备证明，不改变原持久资金责任、账户快照和行情有效期。

Maker首腿准备失败单独记录阶段和受限的错误类别：目录/模式/杠杆/风险档位/持仓订单读取与实际参数不符分别表达，不把准备失败称为交易所拒单。模式未知仍拒绝下单；认证、超时、取消、格式错误不能互相冒充。原连续失败计数、退避、第五次硬暂停、账户复核期限及未知订单核对保持，诊断分类不授予重试或恢复权限。

新增0032保存任务承诺；终态订单、相应风险单位的账户证据、精确持仓/挂单核对后才认定覆盖或释放。初始准备超时/激活失败且尚无真实任务或订单时清理本次暂存记录。已存在任务、未知单和其他责任不删除。

### 同一资金责任只计一次

普通托管建仓在首腿前利用完整持仓/挂单、官方资产行和账户身份建立暂时的资金池归属证据。仅在该池起初没有旧持仓、开放订单、期货保证金或借贷，且当前责任可归属到本任务时启用；既有混池及缺证据场景保留保守检查。官方资产行按实际交易所和结算币种匹配，分所使用各自风险单位，非USDT的换算复用既有公开估值及FX余量。所有信息仍受原准备和账户期限约束。

合格池按完整原批准责任R减去同份官方响应已体现的期货保证金C计算，不能先减covered再减C。C受明确受理/确认成交对应的责任上限以及官方池IM/MM约束，所有池合计不能超过对应官方账户总IM/MM。明确受理的活跃挂单可计入IM冻结上限；MM仍只计确认成交。已撤销的未成交余量、未知单和无remoteId订单不授予抵扣。该资金上限不增加可对冲数量：第二腿仍只按确认成交差额扣除在途数量发送。

官方预估平仓费及挂单成交费已经属于期货冻结项，沿用现行0.075%参数计入责任上限，避免重复保留同一冻结；真实已付手续费和借贷保证金不混入C。实际费用只有在现有费用账本、订单/client身份、成交数量、扣费币种/池及官方现金余额变化都一致时，才从剩余费用责任消费一次；缺证据保留预算，超出费用额度或证据损坏进入明确的资金错误保护。借贷IM/MM始终完整留在官方总指标内，正常费用借贷不自动当成外来交易。

其他同池任务或普通订单先按撤销C后的原保守口径试算，成功登记新责任后才撤销旧优化资格；失败准入不得损伤原任务。新的责任登记会使旧候选的回滚凭证失效。资格不持久化为资金释放，重启/换账户/断线失效；已收到的外来订单/仓位及真实风险仍受原保护。普通asset推送只唤醒既有后台账户读取，不是新的完整账户快照，不延长旧数据寿命。本契约保留原5秒数据传播边界，不承诺发现尚未观测到的外部行为。

### 持仓先于成交回报

同一账户原双腿归属、明确启动基线和有效准备之下，若持仓推送或REST先报告了同向增长，且数量未超过已确认量加明确受理自有订单的剩余量，则暂记为待确认进展。它不增加成交账本、不授予第二腿数量、不释放资金。期间新增/替换Maker在策略和实际发送点分别阻止；随后订单/成交确认的真实差额仍可立即补腿。

已见最大进展及首次时间不会被旧REST、重复推送或部分更新清除/延长。取消后责任不足、反向/越界及原25秒期限到达进入原保护；主动计时不依赖下一条回报或REST完成。Stop、账户变化及真实锁优先，进展标记不能恢复交易。一般无法归属的持仓差异仍走原核对，不把任意差异解释为正常滞后。

长期数据库清理不能删除未释放配对责任的订单与成交证据。只有明确的JSON布尔值`released:true`允许按原期限清理；缺失或损坏的责任数据不能被当作已释放。

正常对冲数量低于对手最小单时不能放大为全部持仓；在同一已有Maker剩余责任内继续累积，已无可继续的原单且仍不可交易则升级人工。盘口、账户或控制权失效时拒绝发送，不以加速为由放宽门禁。

## 发布与实盘验证边界

持仓页面提交“全部平仓”后，浏览器会话内按账户、任务、稳定组及精确两腿保留请求回执，跨标签、页面及暂时空仓显示继续去重。回执只用于显示及禁止重复提交，不授予新平仓权限；新请求仍以当前唯一托管归属及后台控制权检查为准。结果未知保持需核实；停止、KEEP或控制权转交也显示需核实。仅相同任务的权威COMPLETED、两腿零仓且无在途订单可以显示已完成，迟到响应不得使其倒退。旧账户回包不得修改当前账户界面，A任务完成不得关闭B任务的确认框。整页重载后依赖后台当前任务状态，不把内存回执当作持久交易账本。

部署迁移演练精确接受0031或0032的单个追加迁移，核对规定空表、完整索引和真实checksum，原业务数据与旧迁移记录不变。实际准备仍须通过候选及旧镜像的隔离演练。候选发生交易并留下未释放责任后，不能只凭旧版本能打开新数据库就回滚：切换前重新读取当前责任，目标必须声明并通过配对责任执行能力验收；否则须先结清责任，或使用兼容该账本的回滚版本。

恢复验证器与切换检查使用相同的严格责任判断（测试校验两份独立打包脚本的函数字节一致），缺失released视为未释放，非布尔值或损坏JSON拒绝兼容认证。准备阶段在原实例仍正常运行、无维护写入意图且验证器未被恢复容器占用时，备份并原子同步已审查的恢复验证器；保存新旧摘要和安装凭证，失联后核对既有结果，不盲目重放。不得用交易前备份覆盖后续真实订单和成交。

当前请求调度、资金责任及风险锁均由单个运行实例维护。同账号另起一个可交易测试进程，即使使用不同合约，也不共享这些约束。小额实盘应使用真正独立的风险账户，或在单一受控写入实例中执行；不能用交易金额小替代账户隔离。
