# 交易与数据安全

## 账户与权限

每位使用者运行独立实例、数据库，并使用自己的API。API应禁用提现，只开放需要的读取和交易权限，并按平台能力绑定IP。跨所全仓持仓共享保证金，一个任务的损失和异常可能影响其他任务。
同一账号不要运行两个独立可交易实例；它们不能共享本地资金责任、持仓归属、限流和风险锁。分所模式按对应风险单位检查，不能合并不同账户资金。

## 配对执行

普通托管Maker–Taker任务在首腿前核验两腿账户、模式、杠杆、数量和资金条件，并保存批准数量及资金责任。挂出或替换Maker前再次核验有效范围。第二腿按首腿确认成交量，扣除自身已成交和在途数量，仅履行原任务责任。
正常第二腿保留账户新鲜度、精确行情、交易规则、任务归属、批准额度和控制权限检查，不等待重复的账户、杠杆或模式查询。后台发现真实风险仍阻断交易，过期数据不能当作有效。
官方保证金已经体现本任务责任时，只在账户、交易所和结算币种归属可证明的范围内避免重复计量。混合责任或缺少证据仍保守核验，不猜测资金已结算、不改变批量或风险线。已受理挂单可以解释冻结资金，但不能当作确认成交来增加对冲数量。
持仓推送早于成交回报时，原批准范围内的进展暂时阻止新增Maker，随后按确认成交配对；不据此释放资金。未确认进展超时、取消后无法解释或越界仍进入保护。
普通退出按确认成交及时只减另一腿，真实持仓核对仍是本批结束和下一批开始的门槛。保证金紧急减仓保留专属批次和费用责任。小于最小单量的差额不能扩大为全部持仓。
读取有界，写入串行，账号发起间隔及429冷却共用。结果未知的提交或取消先持久记录再全局暂停，不能通过换通道、冷却或重启重发；迟到终态不会自动解除硬暂停。

## 归属与停止

接管旧仓须明确选择账户和真实合约对，证明两腿平衡。相同资产简称不等于同一合约。其他任务、历史任务或已转交的归属不能自动接管。
默认Stop保留仓位并结束自动监控和保护。退出必须明确选择平仓。停止、退出意图、控制权和人工锁跨重启保留；启动为交易unset。恢复须核对事实并由使用者明确操作。

## 证据与恢复

缺失行情、费率、费用或账户字段不能写成零或成功。参考行情只有通过精确合约、单位、源时间和有效期检查后才能用于执行。
未释放资金责任及关联订单、成交不能被维护清理删除。只有明确的布尔值released:true表示已释放；损坏或不明确的责任不能被忽略。
更新或降级须核对目标版本理解现有责任。旧版能打开新表不代表它会执行新规则。不要用交易前数据库覆盖后续真实订单和成交；恢复副本完整也不代表等于当前交易所状态。
故障注入使用隔离网关。真实交易只证明实际样本，少量成交不能代表生产延迟分位数或盈利能力。未解决的高风险问题不能靠降低门槛绕过。

## 持续保护与普通恢复

新的托管启动确认包含本组暂停/重启保护；既有未覆盖组不自动补权限。登记后仍须核实实际责任；未知订单不重放，KEEP、明确只读及撤权优先。正常保证金事件仅在全部证据核清后结束自己的冻结，不清除旧/人工硬锁或补回已减少仓位。详见[托管持仓](managed-positions.md)和[保证金保护](margin-risk-management.md)。
