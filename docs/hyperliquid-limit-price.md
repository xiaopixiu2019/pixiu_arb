# Hyperliquid 限价规则

本契约仅适用于 `HYPERLIQUID_FUTURE_*` 的 LIMIT 订单。其他交易所、市价单、数量算法、全局 Decimal 配置、缓存策略、风险阈值及人工恢复权限保持原有语义。

自动生成的最终限价必须同时满足现有合约 `tick_size` 与 Hyperliquid 非整数价格最多五位有效数字的规则，整数保留其有效数字例外。现有 CrossEx tick 约束继续限制可用小数步长，不从数量精度猜测价格精度。缺失或无效 tick 明确拒绝，不使用默认精度。

采用精确整数运算：BUY 选择不高于原价的最近合法正价格，SELL 选择不低于原价的最近合法价格。没有合法正价格时阻止本次提交。输出普通十进制字符串；自动建仓在价差边界与盘口价选定后处理，托管限价退出使用同一函数。调整后不得突破原经济边界、改变数量或把 Post-only 改成市价。行情变化导致的交易所拒绝仍按既有保护规则处理。

最终提交层仅对上述 Hyperliquid 限价再次核对当前缓存中的合约 tick 与价格合法性；验证在异步权限/资金核对之后、实际网关调用及本地 PENDING_SUBMIT 行创建之前完成。手动非法价格明确拒绝，不静默修改；其他交易所沿用原价格字段及请求构造路径。

风险页的执行警示为独立显示功能：保证金正常仍可与只读或任务风险暂停并存。复用既有风险快照中的 liveEnabled、groups.phase 和已加载任务原因，突出暂停数量与自动执行停止；保留真实保证金指标，不创建保证金事故、不解除任何锁。数据过期时不得宣称执行正常，仅切回 live 也不代表所有暂停任务已恢复。

验证须包括历史 XMR/KIOXIA 价格、买卖方向、整数例外、数量级边界、极小价格、缺失规则、最终网关零非法调用、其他六家请求不变，以及只读/部分恢复/数据过期下的风险显示。新修复不授予部署或恢复实盘权限。
