# 数据恢复与任务连续性

本文件描述现行维护源码的读取和恢复契约；生产是否已采用此行为，须核对实际部署版本与验收记录。公开行情恢复不授予实盘权限。

## 保证金与任务

已显式启用的持续保护与普通任务恢复分离：普通策略的25秒复核期限到期后仍保留人工锁，保护控制器继续有界读取和查询原订单；两次独立匹配快照及当前有效保证金数据核实后，只恢复授权内的保护。不能据此重开普通策略、复活撤权、重发未知订单或忽略账户身份变化。未启用持续保护的账户保持原恢复契约。

保证金账户采样使用长生命周期的独立只读客户端，与其他鉴权调用共享发起间隔和服务端429冷却，不共享被慢请求占住的串行队列。采样仍每2秒调度、4秒总期限、5秒有效窗。总期限包含凭据获取、排队和响应体；取消信号传入系统凭据库及HTTP读取，迟到或已换账户的请求不能发布数据或触发后续读取。

浏览器风险有效期使用现有 HTTP 响应的 `sampledAt + ageMs` 与单调计时的请求往返边界校准服务器时间，以保守年龄上界计算原5秒期限；不直接比较两台机器的墙上时间，不修改交易权限。顶部、风险页、持续保护时间显示及规则编辑使用同一基准。校时基准有效60秒，使用满40秒或当前区间仍宽于500毫秒即后台续期；一次不相交的慢响应只触发复核并保留仍有效的原基准，两份相互一致的新证据才确认时钟变化。续期失败不延长基准或已见采样的到期时间，旧帧和失败响应不能撤销更新的风险状态。账户/连接变化、恢复前台及失效校准须重新读取；核实前显示待核实。网络耗时、真正过期和服务器阻止仍有效。

周期保证金账户的CrossEx汇总读取使用共享鉴权调度器中的单一控制槽；原两个普通读取槽与独立写入槽保持不变，四类工作继续共享100毫秒发起间隔及429冷却。普通页面、组合快照及任务恢复不能占用控制槽；分所账户的多请求展开仍使用普通槽，避免连续控制读取阻塞紧急写入。控制读取不能增加请求发起速率或绕过交易所退避。

本地SQLite的 `SQLITE_BUSY`、`SQLITE_BUSY_SNAPSHOT` 与 `SQLITE_LOCKED` 表示另一个原子写事务仍持锁；托管监控延后250毫秒重试，保留原任务、账户证据和持续保护状态，不把本地锁竞争升级为账户硬暂停。新托管任务在任何远端读取或下单之前建立本地预约时，同类锁竞争按25/100毫秒有界重试；正常成功路径不新增异步让步，持续占锁返回`managed_launch_storage_busy`并清理本次临时预约，不创建任务、订单或保护授权。若后续准备失败且预约清理也持续占锁，则返回`managed_launch_cleanup_busy`并保留明确待清责任，不能冒充可安全重试。其他数据库异常、真实账实冲突、未知订单和账户身份变化仍执行原硬风险路径。

只读发布观察器独立通过同一风险接口建立服务器时间上下界，并记录每次DOM采样的年龄界限；不沿用本机墙钟比较，也不以页面自报状态证明自身正确。校准无法完成则报告证据不足，跨过有效期边界的时间不确定样本不冒充稳定结论；观察必须取得稳定样本，原业务、状态及未授权写入检查不变。

已有账户的本地风险策略、事件和锁状态查询先SELECT，不能为了“确保行存在”每次执行INSERT OR IGNORE；后者即使插入0行仍会申请写锁，与收益Worker发布竞争并可能触发旧快照升级失败。只有首次初始化保留原写入路径。此边界不缓存或延长风险证据、不重试未知交易，也不免除真实风险写入的锁和权限校验。

真实未结束的凭据/账户工作单飞。自定义网关若不响应取消，不会因逻辑超时无限创建调用；持续无法结束的读取保持不可用，25秒复核预算到期后进入原人工核查路径。不能宣称任意不合作网关也能自动恢复。

暂时网络/读取超时、429、服务端暂时不可用及 `margin_account_version_regressed`，复用 `managed_account_rechecking` 并保留原 OPENING 目标、数量、group 和 claims。保证金账户读取在同一有效上下文中抛出的底层 `AbortError` 或 `ABORT_ERR` 统一记为可恢复的 `margin_read_timeout`；账户/凭据/读取代次已变化的迟到结果仍由 context/readEpoch 丢弃，不构成恢复观测，认证、身份、结构及未知订单错误也不因此降级。账户版本倒退的响应仍拒绝，只有身份、指标及逐风险单位版本校验通过后才发布共享账户缓存；被拒绝响应不能更新保证金规划/结算缓存。恢复必须同时获得匹配账户/订单与不同的新鲜保证金观测。

版本倒退复核按账户及各风险单位保存此前已接受版本的下界，记录在现有托管状态中，重启不丢失；缺测单位不清除已接受版本。第一份恢复观测不得低于该下界，第二份须使每个风险单位的远端版本严格前进且持仓/订单一致；仅本地采样时间改变、相同远端版本或汇总最差交易所变化均不能充当第二份证据。重复异常不延长首次复核的25秒期限，已有更短执行期限仍优先。记录新旧版本、单位及请求关联，不记录凭据或完整账户响应。

订单取消和配对责任按[托管恢复契约](managed-positions.md#报价恢复与退出前检查)核清：不重放未知请求，手动EXIT继续核对和撤销剩余Maker；KEEP、明确只读、撤权和控制权转移优先。授权、身份、模式、结构校验错误及未知订单不按普通超时自动恢复，真实保证金风险仍走既有保护流程。版本复核只能解除其临时锁，不能清除任务本地路由拒单暂停或计数；普通成交证明不能越过尚未完成的账户复核。

日志区分凭据阶段、排队取消、响应头和响应体失败，记录安全错误分类、账户上下文、开始/结束、时长与请求关联，不记录密钥或完整账户响应。故障日志附最近30秒窗口的事件循环最大延迟；该值只帮助区分进程迟延，不能单独证明网络或历史根因。

## 实时费率

交易所结果独立完成、独立发布；整次读取有八秒截止和真实在途容量保护，迟到结果不能覆盖新代次。读取诊断包含交易所、费率/页面操作、代次、开始/截止/结束和最后成功时间；失败写入告警日志，完整生命周期供debug日志使用。正常约30秒更新、失败约5秒重试，同时遵守每所Retry-After。超过60秒、非法或缺失的数据不能参与经济退出。

托管任务使用仅费率读取，避免Binance展示ticker/盘口、OKX展示ticker/OI和资产分类阻塞必要费率。页面完整数据单独更新，保留其原展示字段。持仓费率投影必须读取刚刷新的托管缓存，不能刷新后仍返回旧页面缓存。Hyperliquid元数据缓存、单飞与配置在有取消信号的调用间共享。

费率主路仍是各交易所原生REST。备用字段严格保留现行业务口径：Gate原生ticker的rate和周期；Kraken原生ticker的当前绝对小时费率除以mark再换算八小时；Deribit原生ticker的`funding_8h`。Binance、OKX、Bybit和Hyperliquid备用来自CrossEx实时资金费推送，使用已核验且未过期的原生合约周期元数据；它们不能称为独立原生费率源。CrossEx消息时间是该服务的发布证据，不是交易所撮合时间；不用于刷新报价时间。

Binance特殊四小时合约不按八小时误算；OKX不把下一周期时间当作本周期结算时间；Deribit的结算时刻可以未知。未知周期不启用备用。相同源时间的矛盾备用费率失效，必须有严格更新的有效数据才能恢复。

## 行情主备

CrossEx主ticker与现有完整盘口/ticker恢复保留为同源自愈。主连接单合约静默时独立探测，不用备用时间刷新主合约健康；主ticker重订阅与现有恢复共享每分钟八次预算。

用于交易准入的独立原生备用报价使用精确合约接口：Binance/OKX/Bybit/Hyperliquid REST，Gate/Kraken/Deribit WS。只采集有需求且本地CrossEx合约目录状态有效的合约；原生元数据必须核实永续类别、报价/结算币和数量单位。Gate与OKX张数换算为基础资产数量，Deribit线性合约数量不重复乘最小合约单位。Hyperliquid未证明的HIP命名空间不猜测映射；不支持的映射保持不可用。页面排序使用的独立 `reference-quotes` 读取遵循[本地展示接口](integration.md#scoped-public-market-reads-local-loading-optimization)，不取得交易授权，也不替代本节的执行准入来源选择。

Gate原生WS提供另一服务路径，仍属同一供应商；其余原生报价绕过Gate聚合服务。所有路径仍共享本机出口及原交易所风险，不承诺供应商整体或本机网络中断可被覆盖。

主源不合格时采用合格原生候选；原生备用健康期间，CrossEx来源须两个不同前进源时间的合格样本才回切。备用已经失效时可立即采用合格CrossEx样本，不能为防抖继续使用坏数据。源时间15秒、到达差3秒、未来容差2秒保持不变。原生身份有效期、错误合约、数量单位、同时戳冲突与生命周期均参与校验；明确停牌、闭市或无流动性的新帧撤销该源旧报价，旧帧不能复活它。其他合格来源保持独立。

`source=native_venue`与`nativeSymbol/nativeValidUntil`保留原生身份，不伪装CrossEx。`quoteHealth`分别说明主连接、CrossEx来源和原生来源的时间/可用性。原生BBO不使旧last/24小时统计变新。策略订单在所有异步准入之后、提交前再次检查所需报价；订单仍发送到原CrossEx账户和精确symbol。建仓补腿、终态补量及其后减仓沿原修复风险规则处理。托管退出和保证金减仓中明确未派发的行情故障，可按[托管报价恢复契约](managed-positions.md#报价恢复与退出前检查)进入有界核对；它与报价来源切换是不同职责，不因行情恢复而重放整组或清除硬锁。硬暂停后的模式取决于有效持续保护授权，不能一律写成全账户只读。通用定时平仓不因此取得新的恢复权限。

采样最多100个需求合约、4个真实在途REST工作；同所按至少250ms发起间隔公平轮询，每合约目标间隔2秒，过载不能保证该目标周期。HTTP和元数据缓存有界，429退避，WS有Ping/Pong及受限重连。测试通过的19个合约不是全部市场长期可用性的承诺。

## 状态与通知

所有候选报价失效时，任务立即保留缺失事件、阻止依赖该证据的执行并持续探测；Telegram只在报价连续缺失10秒后通知。一般信号缺失保留五分钟门槛。同一轮多个任务合并发送，但每个底层事件仍分别落审计和跨重启去重。只有实际发送过故障通知的事件才发送恢复通知；未越过通知门槛的短暂抖动不会产生孤立恢复消息。价格恢复而费率仍缺失，不结束经济退出缺失事件。必要数据全部恢复后记录完整失败窗口，已通知事件发送恢复，退出条件持续时间重新开始。

报价与经济信号缺失通知针对 `RUNNING` 任务；存在全局风险锁时优先处理风险锁告警，普通缺失和恢复通知暂不扫描。通知调度不改变任务数据恢复或交易权限。

数据恢复通知不是交易恢复通知。已释放或转交责任的旧任务不会自动复活；生产部署和任务恢复仍按[部署文档](deployment.md)及[托管契约](managed-positions.md)授权验收。
