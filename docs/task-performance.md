# 任务净盈亏

## 增量结果与查询边界

本文定义当前计算口径。实际运行版本、账户身份、金额与历史覆盖必须重新核实，不能把旧的“本地实现”或历史结果沿用为当前结论。

`summary()`只读取已发布的托管组阶段结果，并按原规则核对当前持仓、数量、时间及汇率后计算浮盈亏。它不触发采集、不读取历史账单/成交/原始覆盖区间，也不写缓存。后台每秒检查更新与账户上下文，保留原每分钟的近期窗口和历史分段采集；已有新鲜持仓估值优先复用，独立估值读取仍受原5秒间隔及4秒超时约束。

`0034_task_performance_projection.sql`新增可重建的组/账户显示结果、持久进度、变更标记、汇率依赖和合并覆盖区间。首次核实账户后建立监听并受控初始化；输入实际变化与更新标记同事务记录，重复输入不产生历史重算。历史覆盖原始记录保留，合并区间不跨越缺口；重建由后台完成，采集器在合并区间尚未就绪时保守重读。

结果按组发布，归属上下文还包括共享合约、订单身份、交接链、账户成本和历史汇率。沿用两份原报表公式及归属规则。组历史现金分项与实时估值分开；正式账单替代成交估算，费用冲突、缺失FX等仍不能显示为已核对。账户汇总保留原始记录排序，避免分组相加改变高精度舍入结果。

文件数据库的计算由专用Worker线程执行，没有交易网关、凭据或交易执行器；内存数据库测试使用相同计算模块。持久检查点允许中断后继续，只有源版本仍相同才原子发布；主线程读取完整版本。发布通知丢失时，数据库发布版本与输入版本共同防止旧结果冒充当前结果。大结果在写锁外序列化，采集账单按200条分批落库，完整窗口完成后才推进覆盖。

已处理变更标记每次最多清理200条，并等待所有相关已初始化账户确认；原账单、成交、覆盖证据与交易责任不清理。禁止单独重置进度或SQLite序号。组缓存格式版本变化必须受控重建，不能静默复用旧公式结果。所有结果与缓存仅用于财务展示，不能解除风险锁、恢复普通策略或授予下单权限。

## 动态交易盈亏

新增 `trading` 为独立交易口径：已实现价格盈亏 + 剩余持仓浮盈亏 + 已入账资金费 + 交易费用和可归属其他账务。原 `amount/status` 完整成本口径保持兼容，下面原有5%硬门槛仅适用于该旧口径；动态交易口径的5%只提示已知归属差额，不隐藏可计算金额。公共利息及经过核对的完整换汇另列，不能冒称已分摊到任务。

金额、核对状态和新鲜度分别提供。运行、KEEP、部分平仓和清仓任务均显示交易视图；已知迟到账单持续修订，真实成交预估由正式账单替换而非累加。当前浮盈亏仅使用同账户、同合约和方向、数量与任务成交一致的真实持仓及有效汇率，不读取兼容展示的默认零。未知输入保持未知。

内部接管须核实完整同账户交接链、数量和合约；末任务展示整组结果，旧任务标明并入且不重复累计。外部旧仓只在存在有效基线时报告自接管以来的结果。未知或冲突归属不得用容差豁免。

读取接口优先返回本地结果；后台最新与历史采集独立记录成败。短暂失败保留同账户最后可信金额、源时间和延迟标记；重启后必须重新核实账户身份才能加载持久快照。凭据上下文变化使旧结果失效。历史费用、当前估值和页面读取时间不得混用。

所有计算与缓存仅服务财务展示，不授予交易权限、不修改退出或保证金保护。正常新鲜来源收到后5秒内显示是本地验收目标，不能承诺上游账单到达时间或无证据时仍有精确数字。

任务净盈亏是独立只读财务视图，不替代账户净权益收益，不参与交易、经济退出或保证金风控。

已结算净额 = 价格已实现盈亏 + 实际资金费净收付 + 交易费用账单变动 + 可归属其他成本账单变动。TRADING_FEE 的负 change 是成本，正 change 是返还；不再叠加成交 fee，不另外扣滑点。

所有分项保留原币，以账单时点附近 90 秒内的可信历史汇率换算 USDT。未知汇率、账单、归属或覆盖不得按零。当前报价不回填历史。未归属账户成本单独披露；不能把有未核实成本的任务标为最终净收益。

归属绑定核实的账户、完整合约、交易所、远端订单及已验证的任务成交。资金费要求已证明的从零建仓、唯一持仓区间、完整成交覆盖和无其他任务/手动成交干扰；接管旧仓、交接、区间边界及迟到账单无法证明时保留待核对，不按同名币种猜测。任务完成与财务结算分开；KEEP 非零仓仍未结算。

新增收益原始账单和分页覆盖记录持久保留，独立于运行订单一年清理。每轮先抓最新窗口，再有限补历史；失败/重复页/时间越界不推进覆盖。账户切换丢弃旧响应。复用手续费模块的成交/绑定及历史汇率证据；历史分项未核实前不显示最终合计。

任务净盈亏展开显示价格盈亏、资金费、交易费用、其他成本、原币小计、完整性和账户级未归属成本。账户收益已包含费用，禁止再次扣减。持仓组和账户概览的金额统一换算；缺一腿或汇率则汇总不可用。

验收覆盖：重复/冲突账单、非1汇率、缺失汇率、入场/退出费、正负资金费、返佣、旧仓/交接、迟到、部分平仓/KEEP、账户切换、历史清理及跨页覆盖。使用隔离数据库与合成网关；不以测试通过代替生产账务核对。

## 接口与实现

`GET /api/crossex/task-performance` 必须携带 `x-gct-read-intent: task-performance`，不接受账户覆盖参数或写入方法。返回当前核实账户的 taskId、amount、status、reasons、checkedAt，以及 price/funding/fees/other 四分项的换算额、原币、笔数；unallocated 是账户级未归属账务，不等于任一任务的费用。

订单终态核对接受已确认的`FILLED`、`CANCELLED`、`REJECT`、`REJECTED`和`FAIL`。其中`REJECT`是实测CrossEx拒单终态，不能仅因其不是`REJECTED`就把已结束的零成交报价当成未知订单。任何有执行数量的终态仍须核对完整成交覆盖；`PENDING_SUBMIT`、`PENDING_CANCEL`、`OPEN`及未知/未支持状态继续阻断交易净盈亏确认。此兼容仅修正财务显示，不改变交易执行的订单状态或风险锁。

状态 settled 表示截至当前采集时点，已平仓且现有覆盖和证据核对通过；仍可能有迟到账单导致后续修订，不是不可变的交易所结算承诺。pending 不显示最终金额；open 表示任务仍有未结清持仓或生命周期未确认。没有账单的资金费腿保持待核对，不能仅凭当前费率为零推断历史没有费用。

pending/open 时没有已确认账单的分项显示 `—`，不能显示零；有证据的部分金额明确为已确认小计。只有完整核对通过的已结算任务才能把确认无发生的分项显示为零。

## 小额归属差额

对已经平仓、成交/手续费/历史覆盖/汇率均核实的任务，只有剩余问题为已知账单的归属时，允许按总误差不超过估算净盈亏绝对值的 5% 展示 `estimated` 净额（用户后续指令替代原 0.1 USDT 绝对门槛）。页面标记“约”和百分比误差范围，不宣称逐笔最终归属已确认。不能将缺失账单、缺失汇率、冲突、旧仓成本或未知交易类型当成小额差额。

允许纳入估算的范围仅为：与任务已确认资金费共享持仓业务标识的迟到资金费；有明确账单及历史汇率的账户利息、清算费用、破产补偿；以及相同业务 ID、相同时间、USD/Kraken 与 USDT/CrossEx 两腿金额方向相反的完整自动换汇。账户成本逐笔计算归属误差，即使可能来自其他任务也仅作为有界估算，不宣称精确归属；不同账单的正负数不能相抵误差。换汇本金相抵后的历史汇率净差额才是潜在成本，不能按两腿本金绝对值重复计算。任何不完整换汇继续阻断。

估算净额 = 已确认四分项小计 + 已知待归属调整。调整项逐组计入实际带符号金额；归属误差上界为各组绝对金额之和，再加 0.005 USDT 的两位小数显示误差。合计除以估算净盈亏绝对值必须 ≤5%；不得逐条放行后累积越限，净额为零时不使用百分比估算，接近零及亏损均按同一绝对值分母处理。API 的 estimate 字段提供 adjustment、maxError、maxErrorPct 和 tolerancePct；页面只显示百分比误差，展开明细同时展示确认小计和估算调整，原始账单及待归属理由保留。此容差只用于财务展示，不影响下单、经济退出、保证金风控或任何暂停/恢复权限。

`0030_task_performance.sql` 新增 task_pnl_book 与 task_pnl_coverage，原始证据按已核实账户和账单 ID 去重；同 ID 内容冲突保留旧证据并阻断最终收益。收益记录不跟随运行订单的 365 天清理；成交与订单归属复用持久化 fee_trades / fee_order_bindings / fee_binding_coverage。

采集器使用独立统计读取队列，30 秒超时和可取消生命周期，每分钟抓最近一小时及一个最多一天的历史窗口；日窗口分页不完整时缩为六小时，只有实际完整读取的窗口才推进覆盖。回填不早于可信手续费统计起点；更早任务仍保留历史缺口，已有原始记录不删除。历史完成后轮转重读，接收迟到记录。首次升级需要后台补历史，期间显示待核对。历史资金费持仓业务标识跨任务重复或迟到归属不唯一时阻断最终合计。没有改动实盘模式、下单、退出条件或保证金阈值。
