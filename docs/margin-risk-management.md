# 账户保证金风控

本文件是现行行为契约，依据 `margin-risk-monitor.ts`、`margin-risk-service.ts`、`margin-group-plan.ts`、`margin-reduction-evidence.ts` 和托管执行器。任何生产结论都必须重新核对当前账户和运行事实。

## 用户设置与保护范围

新托管任务在启动确认时同时登记本组的普通保证金保护和“暂停期间持续保护”；风险页仍保留已有组的显式授权及撤权入口。登记绑定当前账户和稳定组，不修改阈值或批量算法。启用后，任务PAUSED与人工复核标记不再直接取消其保护资格；规划仍要求真实模式/仓位、有效账户数据、必要报价、原批次预算和费用责任。任务冻结时只有后端受限许可可以通过最终提交门禁。原持久风险锁继续禁止普通新增。

`continuousProtection`返回独立执行状态及各组原因；官方比率正常、status为clear/reducing或收到通知均不代表已成交。共享账户有未决订单时，不能开始无法完整证明预算安全的保证金新首腿；查询原订单及账户恢复不依赖人工点击。停止KEEP、明确readonly、授权组移除仍优先。范围及迁移见[托管持续保护](managed-positions.md#独立持续保护)。

在 `/risk-management` 的原设置入口配置六项阈值。新托管对冲任务的启动确认同时授权本组IMR/MMR自动减仓；授权与任务/claims在同一事务登记，仍由原阶段和数据门禁决定能否执行。普通非托管任务不因此获得授权。旧任务仍由风险页显式选择，部署、恢复和后台刷新不补权限；取消勾选不会被自动加回。追加接管的启动授权覆盖同一稳定groupId的合并仓位。授权不改变live权限、六项阈值或已开始事件的范围。

| 指标 | 预警并禁止新增 | 触发减仓事件 | 结束事件的恢复值 |
| --- | --- | --- | --- |
| IMR默认值 | 110% | 105% | 115% |
| MMR默认值 | 200% | 150% | 220% |

要求有限数值且 `100 < reduce < warn < recover`，单项上限1,000,000%。预警/触发比较严格小于，恢复比较大于等于。任一指标触发事件，恢复须两项同时满足。比率来自官方账户：保证金余额分别除以起始/维持保证金，API小数比率只乘100一次。官方100%边界与这些用户阈值分别处理；验证为零的保证金需求显示“无需求”，缺失不视为零或健康。

自动减仓目前限于核实的 `CROSS_EXCHANGE` 账户内、两腿实际为 `CROSS` 的有效托管组。分所风险单位分别监控和准入，不合并其余额/比例，也不扩大自动保护范围。KEEP、已转交控制权、硬风险锁和未启用live均保留原语义。

事件固定数值策略版本及初始组范围。新批授权取“事件授权组 ∩ 当前勾选组 ∩ 当前控制权”；取消勾选阻止下一批首腿，已成交首腿保留原上限内的配对责任。新增勾选用于后续事件。KEEP、关闭live、硬锁或控制权转交会阻止后续提交。界面同时显示已保存策略和事件有效策略。

### 手动保存与界面限制

手动勾选只是草稿，须依次“预览修改效果 → 确认保存并应用”。以服务端保存名单、当前有效名单及组的authorized状态判断授权；ready只表示规划就绪。

已打开的设置草稿不是授权事实。保存返回版本或范围冲突时，重读完整当前策略和服务端名单后再预览；不能只换 revision 或重提旧草稿。后端版本、账户和授权门禁为最终判定。

## 采样、准入与年化口径

- 后台每2秒调度账户读取，4秒读取期限，按本地请求开始时刻计算5秒有效窗。失败/过期阻止新增风险；资金费、规划参数和通知读取不阻塞账户采样。
- 前端风险页、顶栏和资产页按同一5秒有效窗显示：5000毫秒仍有效、5001毫秒失效。除原有周期刷新兜底，还按当前快照到期时刻安排重绘；新快照、账户变化或卸载清理旧定时器，实际判定始终取当前时间。页面重新获得焦点或可见时立即重绘，不增加账户请求、不延长后端准入期限。
- 公共新增合约订单与策略杠杆准备核实 `support_cross` 和按symbol读取的实际保证金模式。支持/不支持/未知分别表达，旧缓存缺字段为未知；必要只减仓不套用新增风险准入。
- 新增订单使用账户/风险单位预约，计入完整策略需求和降低杠杆带来的额外保证金。明确拒绝才释放预约；未知或未结算风险不释放、不重放。
- 负债已包含在官方账户IM/MM中，不作为新增风险的一票否决。新增准入仍计入本单保证金、保守费用/潜在借款增量和未清费用预约；预算不足或原锁未解除仍拒绝，只减仓入口保持独立。
- 活跃托管任务及持仓范围的费率查询共用约30秒刷新，失败后约5秒可重试；超过60秒、非法或未来时间不参与资金费判断。

组排序年化由 `packages/domain/src/funding-yield.ts` 共用Decimal函数计算：每腿按方向计算 `-sign(q) × 持仓价值 × 8h费率 × 汇率`，合计乘1095、除以两腿实际起始保证金的同币种合计，再乘100。MMR事件按有符号年化升序，真同值按稳定groupId；只取该组准确两腿。已出现MMR触发的事件保持MMR原因直到结束。

仅IMR事件按两腿起始保证金占用降序。有效APR的可执行组先处理；这些组无法继续而仅收益证据缺失时，未知APR组按维持保证金占用降序兜底，并记录原因。未知APR不填0。执行事实、授权或数量规划未知仍阻止下单。

这与 `management.fundingAprPct` 的净费率差退出指标不同，也与账户全部持仓资金费收益除以账户保证金余额的顶部年化不同。三种分母不能互换；当前费率简单年化不是历史收益或盈利承诺。

## 数量规划的实际支持边界

默认使用 `margin-approximation.ts` 与 `margin-projection-plan.ts` 的全账户增量估算，现有七所共用路径。USDT/USDC/USD按约 1:1 规划，真实展示、触发与恢复仍读官方账户，不修改账本或已有负债。其他非稳定资产不按 1 估值。

- 两腿真实全仓、平衡数量、有效报价、官方档位、当前杠杆及实际Taker费率仍必须可核实。原生保证金校准容差为max(0.01美元,金额的0.5%)；不把容差用于订单数量或恢复阈值。
- 普通汇率读取暂不可用不阻断近似规划；已知偏离1超过1%的币种使用有效实际汇率，已发现偏离但估值过期时阻断。币种估值差另留0.5%相关经济变动预算；每腿100bps执行压力预算保留。
- 原有借币保证金包含在官方起点，不重复增加或假设随平仓消失。三个不同有效账户观察的较大借款/负债系数加25%余量作为本批估计；证据不足、新生负债等情况使用100%压力系数。这些是工程估计，不是交易所未来借币阶梯承诺。
- Kraken等内部兑换只保守估计潜在迁移额及成本，不把兑换本金视为亏损，不预支兑换减少负债的收益；不自动换币/还款。默认规划不读取精确参数文件；旧参数模块仅保留隔离模型测试及历史责任兼容，不能覆盖默认近似路径。
- 每批以达到账户两项恢复线的最小合法减仓量为目标，不再采用2%/5%/10%比例阶梯。容量取任务perOrderQuantity、实际可减量及已明确报告的交易所上限，并按共同步长取整；首次和后续批次使用相同规则。目标高于真实容量或首腿安全容量时分批执行，每批成交/结算核清后根据新事实重新计算，不预先重放剩余计划。
- 合约规则成功读取但max_market_size为null时，不因该字段单独阻断，不伪造无限上限；缺合约记录、非法或非正上限仍阻断。最小量、最小金额、步长、费用和成本预约继续校验，不能为凑最小量越过批量/权限上限。
- 非线性规划按现有模型档位/借款边界分段，在每段求最早满足恢复条件的合法数量，并复验候选和相邻步长；不按合约步长遍历全部持仓，也不假定跨档位全局单调。模型计算仍有预算；无法验证完整目标时只能在已核实且有安全改善的范围内执行，不能把未知目标当成零或直接打满未经验证的额度。
- 两种首腿顺序分别压力校验，提交前再用新账户读数检查原批预算；已有100%硬线缺口不能预计扩大。两项均未恢复时都须改善，已在恢复线以上的另一指标允许回落但不能预计跌破恢复线。

### 预检容量与本批计划

readiness.maxBatchQuantity表示基于当前事实核实的单批容量，不是建议减仓量。风险事件中的protection.targetQuantity是估算恢复总量，protection.plannedQuantity才是本批计划。目标仅需60且条件允许时计划60；用户单批上限小于目标时先做合法批次，核清后重算。已满足恢复线时停止新首腿，两次恢复确认保持；正常事件及人工事故锁按下述恢复契约分别处理。

旧事件的baselines/completedBatches保留作历史兼容，不再决定新批数量；已登记批次的quantity、firstLeg、成本预约和配对责任不可因版本升级扩大或重置。

健康账户不会为测试模型减仓。`readiness`区分授权与规划证据；目标量仅为约值，逐批重算，不保证实际成交或恢复。行情/规则缺失、无合法数量、数量不平、未清订单仍不能开始新首腿。

## 执行、结算与恢复

所有订单复用原 `ManagedPositionManager` 和交易runtime：首腿与配对腿均为MARKET/IOC/reduce-only；不创建第二执行线程，不为MMR批次设置“全部退出”意图。

事件批次与托管批次在同一SQLite事务中登记/完成；网络前用 `strategy_clip=margin:<batchId>` 关联本地订单。持久订单表按订单去重，累计已成交及仍可能成交数量共同占用每腿预算；不能只检查单笔上限。

首腿终态核实后，按真实新仓差额配对。差额不可精确表示或不满足最小量则人工锁，禁止ceil扩大差额、整腿回退或往返修剪。未知提交只核对；拒单、不可交易残量和未解释变化保留风险责任。缺关键归属字段的旧批次要求复核，不能猜造完成状态。

| 完成层级 | 工程验收条件 |
| --- | --- |
| 订单核实 | 远端终态与累计成交量明确，重复更新不重复累加 |
| 批次完成 | 订单均核清；每腿 `before − fills = after`；两腿平衡且实际减少，无未归属外部变化 |
| 事件恢复 | 批次完成；后续账户请求、远端订单/账户更新时间、真实仓位IM/MM及账户保证金桶核对满足结算判据；两个不同有效观察轮次间隔至少2秒，均达到两项恢复线 |

首次有效恢复读数即停止新首腿，等待第二轮。失败、过期、任一项回落或责任未清使确认计数清零。旧在途账户响应通过readEpoch作废；HTTP返回时间或持仓偶然相等不能代替结算判据。远端更新时间不是交易所跨接口原子提交序号，上述核对仍需实际适配证据。

已归属成交尚未反映到仓位时进入有界等待，普通退出与保证金批次分别记录等待状态；25秒未确认升级人工。无法由本系统成交解释的外部减少先持久化事故、冻结新增，再在现有权限内有限配平，之后保留硬锁。

同步结算核对准确订单终态、仓位数量、成交之后的账户时间和官方持仓保证金；普通手续费账单延迟不阻断下一批。首次25秒仍不能确认真实交易/账户状态时保留责任并升级人工；后续达到恢复线也不自动清除该锁。

`0029_margin_cost_reservations.sql`持久保存每批未清成本，独立于事件生命周期。官方成交/仓位事实核实后释放多余压力额，剩余费用预约等待准确成交/账单覆盖；重复短时预留可能降低可用额度，但不能漏算成本。事件结束、重启、账户切换不删除旧责任；未结预约关联的原订单和成交不参加365天执行历史清理。规划、准入和最终恢复扣除未清预约；显示的官方指标不被改写。真实成交费或滑点超过预算时全局暂停；账本最终补齐可清成本预约，风险锁仍需人工。

近似批次同时展示“费用明细待对账”和预留金额；已有财务统计继续准确记录原始币种/金额，不将估算当真实费用。

现有配对责任优先；保证金保护与Maker退出在撤单/成交核清后交接，完整退出意图保留。没有可授权保护组时，原有独立完整退出仍依自身授权运行。

正常事件自动恢复仅适用于本进程中新发生、原实盘运行且控制权有效的保证金调节：成交、实际剩余仓位及结算核清，费用已确认或由保守预约覆盖，两次独立新鲜观察相隔至少2秒且两项均达到恢复线后，原子结束本事件和其增仓冻结，原存续任务继续监控剩余量，不补回减仓数量。自动资格不跨进程，不从旧事件或旧增仓锁补授；人工暂停/退出、模式变化、授权/策略版本变化或真实硬故障使本次资格失效。真实事故及旧锁仍需明确复核，不重放建仓或清除托管硬锁。

## 接口、通知与数据

风险页保留账户卡片、保护参数、通知及事件列表，历史保证金图表前端已移除，不再调用 history 接口；后端采样、聚合和 history API 继续保留。

接口示例、CSRF和错误码见[接入文档](integration.md#账户保证金风控接口)。`GET /api/risk/margin` 和WebSocket `risk.margin` 发布账户指标、保存/有效策略、组范围、`valuation`、`protection` 与 `costAccounting`（pendingBatches、reserved）。

`protection.stage` 为planning、pairing、settlement_pending、confirming_recovery或blocked；另含原因、确认次数、批次/任务ID、计划量、目标量、APR和兜底标识。快照status=blocked也可能只是无授权组/无计划，不能直接等同于托管硬风险锁。

原始风险采样保留24小时、分钟聚合30天，长窗口保留实际极值和缺测；不回填启用前历史。账户键绑定profile、核实的交易所身份及风险单位。迁移0024保存策略/事件/采样，0028追加能力列与远端订单时间，0029保存独立费用预约；不改已应用迁移。

Telegram为终端共用：`/secure/telegram`安全录入，状态接口不回显token，失败不阻止风险计算；远端接受不等于用户已读。配置、删除及测试消息各自沿用CSRF/intent和存储回滚，账务库不存token。

故障、并发、部分成交、重启和反例在隔离数据库/合成网关验证，代码变更运行完整 `npm run verify`。更新按[公开部署指引](deployment.md)核对实际版本、mode、仓位、订单、claims及风险责任；部署不修改用户阈值、授权组或自动恢复硬锁。

源码/迁移入口见[架构](architecture.md#account-margin-protection)。工件、校验和截图只在忽略的 `data/` 保留当前最终证据；备份与回滚按[公开部署指引](deployment.md)管理，不随源码提交。

## 读取连续性

保证金采样使用独立只读队列，并与其他鉴权客户端共享发起预算/429冷却；凭据读取与响应体都受同一四秒期限约束。暂时读取缺失保留建仓意图，恢复仍须原对账和权限规则；真实风险不能转成普通数据恢复。见[数据恢复与任务连续性](data-recovery.md)。


## 普通配对建仓资金承诺

[配对执行契约](paired-execution.md)将普通托管Maker–Taker的两腿准入放在首腿前。新增持久任务承诺与本章保证金减仓成本预约分开；所有新增订单、资金转出和手动杠杆变更均须尊重未清承诺。官方指标展示、现有公式和预警线不变。第二腿按当前有效官方指标、实际未覆盖订单责任及原批准额度做本地核验，不能重复加上整个未来任务预算。分所覆盖证明逐腿使用对应风险单位；未知身份、未知订单或未确认覆盖不得释放。未覆盖责任在证据不足时保守计入，资金边界可能阻断交易，不能假装事实齐全。
